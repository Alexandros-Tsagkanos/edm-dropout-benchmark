# Reproducing the results in RESULTS/

Every artefact in this folder was produced by the code in `../CODE/` and `../DATASETS/`.
Below is the exact command that regenerates each part. Run them from the repository root (the
folder containing `run_all.py`) unless a `cd` is shown. You need Python 3.9+; dependencies
install themselves from `requirements.txt` on first run, and the runners enable UTF-8 output on
Windows automatically. No GPU is required. No report (PDF/TeX) is produced — the technical
report in `../FINAL REPORT/` is hand-written.

Everything at once. `python run_all.py` does a single-seed run of every dataset
(Realinho + OULAD + the real-text check) and writes all of the single-seed / forum outputs below.
The per-dataset commands beneath reproduce each piece on its own.

Folder map

| Folder | What it holds |
|---|---|
| `CODE/` | generic phases (`common.py`, `phase2..phase10`, `phase3b_smote`, `bootstrap_ci`) |
| `DATASETS/<ds>/` | raw data + that dataset's preprocessing + `run_single.py` + `run_multiseed.py` |
| `RESULTS/<ds>/` | the outputs described below |

---

## 1. Realinho — single seed · ~6 min, CPU only

```
python DATASETS/realinho/run_single.py
```

Runs `phase1_preprocessing.py`, then `CODE/phase2..phase10` + `phase3b_smote` + `bootstrap_ci`
(seed 42). Produces `RESULTS/realinho/single_seed/`: `data/` (processed.npz, synth arrays,
baseline_mlp.pt, student_comments.csv), `results/` (per-phase JSON, `master_comparison.csv`,
`experiment_summary.md`), `figures/` (one PNG per phase + `master_summary_metrics.png`).

## 2. Realinho — 10-seed robustness study · ~50 min

```
python DATASETS/realinho/run_multiseed.py 10
```

Produces `RESULTS/realinho/multiseed/`: `seed_<k>/` (one full run per seed), `aggregate.json`
+ `aggregate_summary.csv` (mean±std + paired Wilcoxon), `fig_headline_f1_multiseed.png`,
`fig_phase8_pareto_multiseed.png`. The committed `Result_Report.pdf` in that folder is a pre-rendered summary built separately, not regenerated by this command.

## 3. OULAD — single seed (second dataset) · ~6 min

```
python DATASETS/oulad/run_single.py
```

Runs `prep_oulad.py` (demographics-only adapter — the registration tables would leak the
withdrawal label), then `CODE/phase2..phase8` + `phase3b_smote` (seed 42). Produces
`RESULTS/oulad/single_seed/` (`data/`, `results/`, `figures/`).

## 4. OULAD — 10-seed cross-cohort study · ~12 min/seed

Resumable, one seed at a time (recommended on a laptop that may sleep):

```
cd DATASETS/oulad
python run_multiseed.py next          # runs the next unfinished seed, then stops
# ...repeat until all 10 seeds are done...
python run_multiseed.py aggregate 10  # build the aggregates from finished seeds
```

Produces `RESULTS/oulad/multiseed/`: `seed_<k>/`, `aggregate.json`, `oulad_summary.csv`,
`fig_oulad_f1.png`.

## 5. Real-text protocol validation (forum-post urgency) · ~2 min

(Downloads DistilBERT, ~250 MB, on first run.)

```
python DATASETS/forum_urgency/phase9b_realtext.py
```

Produces `RESULTS/forum_urgency/`: `results/realtext_urgency.json`,
`figures/realtext_urgency.png` (urgency detection, AUC ≈ 0.82 — urgency, not dropout).

## 6. Self-labelled SSL baseline (Co-Forest / Self-Training) · ~5 min Realinho, ~25 min OULAD

The self-labelled SSL comparison reported in §"Self-labelled SSL baseline" of the report.
Compares supervised-on-seed vs Self-Training vs Co-Forest (Li & Zhou 2007 reimplementation,
`CODE/coforest.py`) vs fully-supervised, across labelled ratios 1/2/5/10 %, with F1/MCC.

```
python CODE/ssl_baseline.py                                              # Realinho (10 label-seeds)
$env:PROJECT_ROOT="RESULTS/oulad/single_seed"; python CODE/ssl_baseline.py --label-seeds 5
```

Writes `RESULTS/<dataset>/single_seed/results/ssl_baseline.json` and `.../figures/ssl_baseline.png`.
The tag (and output dataset) follows `PROJECT_ROOT`. Smoke: add `--label-seeds 3 --ratios 0.02 0.10`.

## 7. Post-hoc rigor & competitor re-assessment (`CODE/analysis/`) · seconds–minutes

Behind the report's familywise-error footnote, the §"How much signal does the simulated text inject?"
quantification, the §"Phase 9b breadth" six-construct validation, and the §"Re-assessing contemporary
multimodal-dropout claims" subsection. Outputs land in `RESULTS/analysis/` (already committed).

```
python CODE/analysis/multiple_comparisons.py        # Holm/Bonferroni over the multi-seed Wilcoxon tests (no torch)
python CODE/analysis/simulated_text_mi.py           # exact MI of the Phase-9 synthetic comments (0.278 bits)
python CODE/analysis/stanford_multilabel_protocol.py  # 6-construct real-text validation (needs torch+transformers)
python CODE/analysis/triad_synthetic_text_mi.py     # text-only dropout AUC on TRIAD-Drop's GPT comments
```

The two text scripts download DistilBERT once and read the bundled third-party corpora under
`DATASETS/{stanford_mooc_posts,triad_drop}/` (see their `provenance_*.md`). `CODE/analysis/morf/` is a
scaffold for a real-text result via the MORF enclave — not runnable without an institutional DUA.

## Notes

- The numbered phases share one fixed train/test split frozen by Phase 1 (or `prep_oulad`
  for OULAD); later phases read the frozen `processed.npz`, so every number on a given dataset
  comes from the same split.
- The neural phases (VAE, diffusion, fair-MLP, DQN) can drift by a few thousandths across
  `torch`/`xgboost` versions — this is why the headline claims rest on the 10-seed studies
  (mean±std + paired Wilcoxon), not any single run. Deterministic phases (Random Forest, the
  LogReg active learner, the distributional-fidelity scores) reproduce exactly.
- The technical report `../FINAL REPORT/REPORT.pdf` is hand-written LaTeX; it is not generated
  by the code. It embeds copies of the figures produced above.
